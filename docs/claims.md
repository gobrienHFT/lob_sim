# Assumptions and limits

`lob_sim` separates feed facts from modeled behavior. The table below says what
the current implementation supports and what it cannot establish. Results that
fall outside these conditions are diagnostic, not current economic results.

| Area | What the implementation supports | What it does not establish |
| --- | --- | --- |
| Capture | Receipt identity is assigned before payload parsing. Checksummed schema-v3 envelopes record route connect/failure, snapshot attempts/rejections, and normal trailer boundaries. Envelope identity fields remain non-empty strings; receipt sequence, monotonic time, and stream/sync epochs are exact non-negative integers at every boundary; coercible values are rejected rather than rewritten. Snapshot rejection evidence preserves raw levels without rounding; structurally unrecordable responses become explicit rejection events. Non-finite numeric fields fail schema validation. A single asynchronous writer uses a hard-bounded queue; overflow or sink failure aborts rather than silently dropping and continuing, leaves a recoverable partial tail, and emits sanitized failure evidence. Replay propagates schema, adapter-normalization, parse, and overflow failures into an independent capture-validity boundary that clears execution state and halts strategy actions before invalid normalized events reach book/fill state. Segment and normalized-Arrow file hashes are computed incrementally; successful manifests hash writer completion, queue/outstanding high-water and lag statistics. | This does not establish zero packet loss without venue-side telemetry, exchange timestamp causality, or a zero-drop/24-hour-soak result without representative external data. |
| Book reconstruction | Binance USD-M market-by-price epochs are reconstructed only while sequence and invariants are valid. Negative/reversed update IDs, a depth batch or REST snapshot that would cross or otherwise corrupt the book are discarded atomically, invalidate the sync epoch, and require a fresh snapshot bridge; a gapped or overflowed pre-snapshot buffer is discarded rather than retried indefinitely. | Participant identity, hidden liquidity, or private order-level FIFO. |
| Stream validity | Depth and trade routes have independent validity. Trade reconnects preserve a valid book but clear stale flow and terminate trade-dependent live/pending state before prospective recovery. | Recovering missed public trades or proving execution during an invalid interval. |
| Clocks | Schema-v3 logical time is `(recv_monotonic_ns, recv_seq)`; missing receipt identity and receipt-monotonic regression are fail-closed boundaries. Pending markouts and live execution state are invalidated, strategy actions halt, and raw timestamps remain auditable. Legacy compatibility traces remain readable but clock-dependent results are diagnostic-only. | Measured exchange, network, or colocated latency. |
| Execution | Every public-L2 fill names its scenario, resolvable input-record evidence, source-specific validity intersection, synthetic queue trajectory, configured latency draws, lifecycle state and fee model. Coverage is audited across summary, trades and trace exports. | It does not recover true Binance fills, counterfactual market impact, private FIFO, measured latency, or true bounds. |
| Synthetic venue | The synthetic mode has exact participant/order IDs and price-time priority. | Historical Binance FIFO equivalence. |
| Python/Rust agreement | Python and Rust agree on generated fixed-point book batches, a restricted single-price public-L2 trade queue-ahead transition, exact-synthetic new/cancel/replace lifecycles, integer-nanosecond scheduler transitions, per-symbol live-plus-pending lot reservations, cross-symbol gross-notional reservations over externally marked inventory, fixed-point fill accounting/markouts, fixed/empirical/stress-tail scenario-latency sampler traces, and a composed smoke contract that applies book, scheduling, queue, risk, accounting, markout, and epoch transitions in one deterministic sequence, including deliberate rejections. | This does not extend to end-to-end `SimulationEngine` parity, engine-integrated public-L2 execution scenarios, public-L2 fill truth, participant FIFO, engine-integrated latency/risk/accounting, or manifest parity. |
| Risk/accounting | Live-plus-pending exposure, optional gross portfolio-notional reservations, post-only arrival checks, fees, gross/net PnL and missing marks are auditable. Open positions without an active book or instrument metadata fail closed in valuation and remain visible as unvalued inventory. Configured markout horizons report coverage and observation lag, with epoch-invalidated samples excluded. | Engine-integrated Rust risk/accounting parity, capital deployment, live profitability, or risk-model completeness. |
| Reproducibility | Repeated runs and committed fixtures are hash-identical; JSON-only checkpoint/resume revalidates input/config identity and matches uninterrupted state, trace, and summary hashes. | Checkpoint resume does not append streaming audit sinks implicitly, and deterministic replay is not a causal statement about an unavailable venue state. |
| Simulation persistence | Ordinary runs stream causal trace, fill and markout rows with tape-duration-independent retention. Live order state, pending markouts, and public depth/trade overlap credits are bounded by explicit configuration or the overlap window. Fsynced partials, an incomplete sentinel and the final hashed manifest distinguish failed from complete bundles; economic simulation rejects visible capture partials while forensic replay can recover only fully checksummed prefix records. | Filesystem-wide atomicity across every file, recovery of an un-fsynced tail, or bounded memory beyond the declared live state, pending-markout cap, and overlap-window credit contract. |
| Pack audit | Bounded bundles are independently reparsed sequentially; serialized fill/markout chains, trace correspondence, input evidence IDs, distinct filled orders, per-file hashes, a content-addressed non-manifest bundle digest, configuration/code provenance identities, and the versioned claim-gate projection are checked without retaining detail rows in Python memory. Exact growing sets use a temporary on-disk SQLite index, and derived packs fail closed behind an incomplete sentinel. | Constant disk usage, immunity to a single arbitrarily large row, or proof that a successful self-audit makes the market model true. |
| Research | Paired scenario/latency studies can report markouts, uncertainty and robustness. | Alpha after an underpowered or holdout-tuned study. |
| Performance | Benchmarks document a pinned build, corpus and host. | Trading latency, Jane Street equivalence, or production readiness. |

Treat a report as diagnostic until it has a complete validity interval, a replay
validity timeline, and a self-describing manifest. A final book that
resynchronizes after an invalidated epoch does not erase that interval.

# Claim / non-claim matrix

`lob_sim` is a deterministic research laboratory, not a live trading stack. The
public evidence should be read using this matrix:

| Area | Defensible claim | Explicit non-claim |
| --- | --- | --- |
| Capture | Receipt identity is assigned before payload parsing. Checksummed schema-v3 envelopes record route connect/failure, snapshot attempts/rejections, and normal trailer boundaries. Snapshot rejection evidence preserves raw levels without rounding; structurally unrecordable responses become explicit rejection events. Non-finite numeric fields fail schema validation. A single asynchronous writer uses a hard-bounded queue; overflow or sink failure aborts rather than silently dropping and continuing, leaves a recoverable partial tail, and emits sanitized failure evidence. Segment and normalized-Arrow file hashes are computed incrementally; successful manifests hash writer completion, queue/outstanding high-water and lag statistics. | Zero packet loss without venue-side telemetry; exchange timestamp causality; zero-drop or 24-hour-soak claims until representative external evidence exists. |
| Book reconstruction | Binance USD-M market-by-price epochs are reconstructed only while sequence and invariants are valid. | Participant identity, hidden liquidity, or private order-level FIFO. |
| Stream validity | Depth and trade routes have independent validity. Trade reconnects preserve a valid book but clear stale flow and terminate trade-dependent live/pending state before prospective recovery. | Recovering missed public trades or proving execution during an invalid interval. |
| Clocks | Schema-v3 logical time is `(recv_monotonic_ns, recv_seq)` and regression is fail-closed. | Measured exchange, network, or colocated latency. |
| Execution | Every public-L2 fill names its scenario, resolvable input-record evidence, source-specific validity intersection, synthetic queue trajectory, configured latency draws, lifecycle state and fee model. Coverage is audited across summary, trades and trace exports. | True Binance fills, counterfactual market impact, private FIFO, measured latency, or true bounds. |
| Synthetic venue | The synthetic mode has exact participant/order IDs and price-time priority. | Historical Binance FIFO equivalence. |
| Differential proof | Python and Rust agree on generated fixed-point book batches, exact-synthetic new/cancel/replace lifecycles, integer-nanosecond scheduler transitions, per-symbol live-plus-pending lot reservations, cross-symbol gross-notional reservations over externally marked inventory, and fixed-point fill accounting/markouts, including periodic state hashes. | End-to-end engine parity, public-L2 fill parity, engine-integrated portfolio-notional risk or accounting parity, or manifest parity. |
| Risk/accounting | Live-plus-pending exposure, optional gross portfolio-notional reservations, post-only arrival checks, fees, gross/net PnL and missing marks are auditable. | Engine-integrated Rust risk/accounting parity, capital deployment, live profitability, or risk-model completeness. |
| Reproducibility | Repeated runs and committed fixtures are hash-identical; JSON-only checkpoint/resume revalidates input/config identity and matches uninterrupted state, trace, and summary hashes. | Checkpoint resume does not append streaming audit sinks implicitly, and deterministic replay is not a causal claim about an unavailable venue state. |
| Simulation persistence | Ordinary runs stream causal trace, fill and markout rows with tape-duration-independent retention. Live order state, pending markouts, and public depth/trade overlap credits are bounded by explicit configuration or the overlap window. Fsynced partials, an incomplete sentinel and the final hashed manifest distinguish failed from complete bundles. | Filesystem-wide atomicity across every file, recovery of an un-fsynced tail, or bounded memory beyond the declared live state, pending-markout cap, and overlap-window credit contract. |
| Evidence-pack audit | Bounded bundles are independently reparsed sequentially; serialized fill/markout chains, trace correspondence, input evidence IDs, distinct filled orders, per-file hashes, a content-addressed non-manifest bundle digest, and configuration/code provenance identities are checked without retaining detail rows in Python memory. Exact growing sets use a temporary on-disk SQLite index, and derived packs fail closed behind an incomplete sentinel. | Constant disk usage, immunity to a single arbitrarily large row, or a claim that successful self-audit proves the market model is true. |
| Research | Paired scenario/latency studies can report markouts, uncertainty and robustness. | Alpha after an underpowered or holdout-tuned study. |
| Performance | Benchmarks document a pinned build, corpus and host. | Trading latency, Jane Street equivalence, or production readiness. |

Any report lacking a complete validity interval or a self-describing manifest is
diagnostic only.

# Futures Fill Assumption Envelope

This sample runs the committed futures walkthrough input through `conservative`, `base`, and `aggressive` passive-fill assumptions.

Public L2 cannot prove private fills. The profiles are assumption bounds, not private execution truth. Robust conclusions should survive conservative/base/aggressive. Conclusions that only work under aggressive assumptions are weak.

## Command

```bash
python experiments/run_fill_assumption_envelope.py --file docs/sample_outputs/futures_replay_walkthrough/input_fixture.ndjson --env .env.example --out-dir docs/sample_outputs/futures_fill_assumption_envelope
```

## Files

- [`fill_envelope_summary.json`](fill_envelope_summary.json): machine-readable three-profile comparison.
- [`fill_envelope_summary.csv`](fill_envelope_summary.csv): flat profile rows for spreadsheet inspection.
- [`fill_envelope_report.md`](fill_envelope_report.md): markdown report for reviewer reading.
- `conservative/`, `base/`, and `aggressive/`: per-profile simulation output packs generated by the runner.

On this tiny fixture, the conservative profile records the depth-only reduction as unmatched unknown/cancel-like public consumption and produces no fill. The base and aggressive profiles produce one `agg_trade` passive fill. That difference is exactly why the envelope exists.

See [`../../fill_assumption_envelope.md`](../../fill_assumption_envelope.md) for the runner contract and interpretation rules.
